# Регламент технического обслуживания

## 1. Общие положения

Настоящий регламент определяет порядок планового и внепланового технического
обслуживания (ТО) камерных модулей на базе RV1126B.

Ответственный за выполнение — технический специалист (оператор системы).
Факты проведения ТО фиксируются в журнале обслуживания (бумажном или в системе).

---

## 2. Периодичность планового ТО

| Вид работ                                | Периодичность    |
|------------------------------------------|------------------|
| Очистка оптики и корпуса                 | 1 раз в месяц    |
| Проверка крепежа и герметичности         | 1 раз в квартал  |
| Проверка ориентации камер                | 1 раз в квартал  |
| Проверка IR подсветки                    | 1 раз в квартал  |
| Аудит точности системы                   | 1 раз в месяц    |
| Обновление firmware и моделей            | По регламенту обучения |
| Резервное копирование конфигурации       | 1 раз в месяц    |
| Полная диагностика + стресс-тест         | 1 раз в год      |

## 3. Ежемесячное ТО

### 3.1 Очистка оптики

1. Отключить IR подсветку (GPIO1 LOW или `systemctl stop traffic_ai`).
2. Протереть защитное стекло камеры мягкой безворсовой салфеткой, смоченной
   изопропиловым спиртом (70 %).
3. Проверить отсутствие царапин, трещин, конденсата на стекле.
4. Проверить корпус на наличие паутины, птичьего помёта, пыли в вентиляционных щелях.
5. Включить систему, убедиться в отсутствии артефактов на изображении.

> Запрещено: использовать абразивные материалы, растворители, сжатый воздух
> направленный внутрь корпуса.

### 3.2 Аудит точности (ежемесячно)

Подключиться к веб-интерфейсу Grafana (`http://<server>:3000`):

1. Открыть дашборд **«Качество детекции»**.
2. Проверить за прошедшие 30 дней:
   - Процент событий с confidence < 0.70 (норма: < 5 %).
   - Количество дублирующихся событий по одному track_id (норма: < 2 %).
   - Наличие аномальных всплесков (> 3× среднесуточного числа событий).
3. Если показатели вне нормы — инициировать дообучение по регламенту обучения.

### 3.3 Резервное копирование конфигурации

```bash
ssh root@<device_ip> "tar czf /tmp/config_backup.tar.gz /opt/traffic_ai/config/"
scp root@<device_ip>:/tmp/config_backup.tar.gz \
    backups/config_<device_id>_<YYYYMMDD>.tar.gz
```

## 4. Квартальное ТО

### 4.1 Проверка крепежа и герметичности

1. Осмотреть стойку крепления: ослабленные болты затянуть до момента 8 Н·м.
2. Проверить кабельные вводы (PG-гланды): отсутствие трещин, люфта кабеля.
3. Проверить IP67-прокладку корпуса: следы деформации, сухость.
4. При обнаружении влаги внутри корпуса — немедленный внеплановый ремонт.

### 4.2 Проверка и юстировка камер

Подключиться к RTSP-потоку (`rtsp://<device_ip>:8554/front`):

**Фронтальная камера:**
- Полоса движения должна занимать центральные 60 % ширины кадра.
- Вафельная разметка должна полностью входить в кадр.
- Горизонт кадра должен быть параллелен дорожной разметке (допуск ± 2°).
- Номерной знак авто на расстоянии 6 м должен занимать ≥ 60 пикселей по ширине.

**Кабинная камера:**
- Зона рук водителя должна занимать левые 50 % кадра.
- Верхняя часть туловища водителя должна быть полностью в кадре.

При отклонении — ослабить крепёжный кронштейн, выровнять, затянуть.
После юстировки обновить полигон вафельной зоны в `firmware/config/zones.json`
и загрузить через REST API:

```bash
curl -X POST http://<server>:8080/api/cameras/<cam_id>/zones \
     -H "Content-Type: application/json" \
     -d '{"name":"waffle_main","polygon":[[0.30,0.40],[0.70,0.40],[0.70,0.75],[0.30,0.75]]}'
```

### 4.3 Проверка IR подсветки

1. Перевести систему в ночной режим (закрыть объектив рукой или снять после 22:00).
2. Убедиться, что IR подсветка включается автоматически.
3. Проверить равномерность подсветки в кадре — отсутствие тёмных зон и пересветов.
4. Замерить ток потребления IR: норма 2.2–2.8 А при 12 В. Отклонение > 20 % —
   замена LED-модуля.

## 5. Годовое ТО

### 5.1 Полная диагностика устройства

```bash
ssh root@<device_ip>

# Состояние системы
uptime
free -h
df -h
cat /sys/class/thermal/thermal_zone*/temp   # температура CPU/NPU

# Нагрузочный тест NPU (24 ч)
/opt/traffic_ai/tools/npu_stress_test --duration 86400

# Проверка eMMC на bad blocks
badblocks -v /dev/mmcblk0

# Журнал ошибок за год
journalctl -u traffic_ai --since "1 year ago" --no-pager | grep -E "ERROR|WARN" | wc -l
```

Допустимые значения:

| Параметр               | Норма               |
|------------------------|---------------------|
| Температура CPU (idle) | < 55 °C             |
| Температура CPU (нагрузка) | < 75 °C         |
| Bad blocks eMMC        | 0                   |
| Ошибок в журнале       | < 50 за год         |

### 5.2 Замена расходных материалов

| Компонент              | Срок службы   | Признак замены                   |
|------------------------|---------------|----------------------------------|
| Защитное стекло камер  | 3–5 лет       | Царапины, помутнение             |
| Уплотнительная прокладка | 2–3 года   | Деформация, трещины              |
| IR LED модуль          | 30 000 ч      | Снижение тока > 20 % от нормы   |
| Термопаста SoM         | 3 года        | Температура CPU > 80 °C в норм. режиме |
| Блок питания DC-DC     | 5 лет         | Выходное напряжение вне 4.9–5.1 В |

### 5.3 Обновление ПО

1. Проверить наличие новой версии firmware в репозитории.
2. Создать резервную копию текущих моделей и конфигурации.
3. Обновить по процедуре:

```bash
# На сервере разработки
git pull origin main
make release   # сборка под RV1126B

# На устройстве
scp traffic_ai root@<device_ip>:/opt/traffic_ai/bin/
ssh root@<device_ip> "systemctl restart traffic_ai && journalctl -u traffic_ai -f -n 50"
```

## 6. Внеплановое обслуживание

### 6.1 Критерии экстренного вызова

| Ситуация                                          | Реакция              |
|---------------------------------------------------|----------------------|
| Устройство не отвечает на heartbeat > 10 мин      | Выезд в течение 2 ч  |
| Отсутствие событий при наличии трафика > 30 мин   | Выезд в течение 2 ч  |
| Обнаружена влага внутри корпуса                   | Немедленный выезд    |
| Механическое повреждение корпуса или стойки       | Выезд в течение 4 ч  |
| Температура CPU > 85 °C по heartbeat              | Удалённая диагностика + выезд |

### 6.2 Диагностика удалённо (без выезда)

```bash
# Статус сервиса
ssh root@<device_ip> "systemctl status traffic_ai"

# Последние 100 строк лога
ssh root@<device_ip> "journalctl -u traffic_ai -n 100 --no-pager"

# Температура и нагрузка
ssh root@<device_ip> "top -bn1 | head -5 && cat /sys/class/thermal/thermal_zone*/temp"

# Тест камер
ssh root@<device_ip> "/opt/traffic_ai/tools/cam_check"

# Перезапуск (если нет аппаратных проблем)
ssh root@<device_ip> "systemctl restart traffic_ai"
```

### 6.3 Аппаратный сброс

Если SSH недоступен и heartbeat отсутствует > 15 мин:

1. Отключить питание 12 В на 30 секунд.
2. Подключить питание обратно.
3. Ожидать восстановления heartbeat в течение 3 минут.
4. Если не восстановился — выезд на объект.

## 7. Журнал обслуживания

Каждое ТО фиксируется в журнале. Обязательные поля:

| Поле               | Описание                                         |
|--------------------|--------------------------------------------------|
| Дата               | Дата проведения ТО                               |
| Устройство         | ID камеры, адрес объекта                         |
| Вид ТО             | Плановое / внеплановое                           |
| Исполнитель        | ФИО технического специалиста                     |
| Выполненные работы | Перечень выполненных пунктов                     |
| Выявленные дефекты | Перечень дефектов (или «не выявлено»)            |
| Устранённые дефекты| Что и как устранено                              |
| Следующее ТО       | Запланированная дата следующего ТО               |
| Подпись            | Подпись исполнителя                              |
